# Build my Open City contribution

You are my coding agent. Build the change I describe below in Open City, show it to me in the local game, and wait for my approval before submitting it to the shared project.

## 1. Build locally

- Use the existing checkout of https://github.com/HareliField/OpenCity, or clone it if needed. Before editing, read AGENTS.md, CONTRIBUTING.md, and the City rulebook and How contributions work sections in asphalt-heat/README.md. Follow any instructions that apply to your checkout. Preserve other people's work.
- Classify the idea under the rulebook. Build a scoped change that fits the existing city. Flag shared-system or release changes for maintainer review. If the idea is outside the rules, explain the rule and suggest a grounded alternative before editing.
- Locate the change in the city and check its connections. Use the design guide to decide who owns, lives in, operates, or visits it, how people reach it, and what changes with the day, hour, staffing, or weather where relevant. State how ordinary play and one relevant variation should work.
- Reuse the game's existing systems where they fit. Run the relevant checks and record what you verified. If you have chat access only, hand off the prompt and idea to a coding session with local files, a terminal, the Codex in-app browser, and GitHub access for the later PR step. Report unavailable capabilities accurately.

## 2. Show me the change

- From `asphalt-heat/`, start the game with `python3 tools/serve.py`. If the port is busy, use `--port` with a free port.
- Open `http://127.0.0.1:8765/index.html?agent=1` (or the port you selected) in a separate Codex in-app browser tab owned by this session. Launch and relaunch with sound off. Press Play, verify the in-game control reads **Sound off**, and leave sound off. Use the Codex in-app browser exclusively. If it is unavailable, report the blocker and leave the game closed.
- Expand **Agent controller**, run `{"op":"help"}`, and use `places`, `jump`, `world`, and `observe` as needed to reach and exercise the change. For a release tooling change, also show the relevant test or dry run. Show me the local game tab, where and how to try the change, and what you verified.

## 3. Ask before opening the PR

Ask me: **"Do you want me to submit this previewed change as a pull request to the shared Open City project?"** Wait for a clear yes. Until then, keep the work local, including when project instructions normally call for pushing. If I ask for a revision, update the preview and ask again.

After I say yes, commit the previewed change, push a contribution branch to my GitHub fork or an authorized feature branch, and open a PR against the upstream default branch using GitHub tools or `gh`. Include what changed, where to try it, verification results, asset sources if applicable, and anything that needs maintainer review. Give me the PR link so I can share it with the city reviewer. Leave the rules decision, merging and releasing to the project reviewers.
